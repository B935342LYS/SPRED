# 2.14. 터치 편집과 두 손가락 이동 명세

작성일: 2026-11-06
상태: T1~T3 구현 및 T5 사용자 요청 배포 완료(`01a7cbc`) / T4 실기기 확인 대기

## 1. 목적과 범위

편집 모드의 악보에서 한 손가락은 기존 도구의 셀 입력, 두 손가락은 화면 이동으로 사용한다. 모바일 기본 스크롤바를 직접 조작하기 어렵다는 사용자 확인을 반영한다. 모바일 전체 편집 UI 지원을 선언하는 대신 터치 기본 편집과 가로·세로 이동만 추가한다.

- 적용 대상: `pointerType === "touch"`이며 악보 편집 영역에서 시작한 접촉. 모바일 UA 판별을 사용하지 않는다.
- 보기 모드: 기존 브라우저 스크롤을 유지한다.
- 마우스·펜: 기존 편집 동작을 유지한다. 빠른 연속 클릭을 터치 개수나 클릭 간격으로 판별하지 않는다.
- Ctrl 기반 범위 선택·우클릭의 터치 대체, 핀치 확대, 관성 이동, 자동 가장자리 스크롤은 이번 범위 밖이다.
- parser/analyzer/renderer/audio 데이터 계약과 ScoreFile·프리셋 형식을 변경하지 않는다.
- 최초 요청은 명세 및 계획 고정이었고, 2026-11-06 후속 사용자 요청으로 제품 구현을 진행했다. 커밋·배포는 별도이며 현재 단계는 9절을 따른다.

관련 기준: `2.2` UI 상태, `2.8` 편집 산출물 갱신, `2.9` 범위 선택, `2.10` Undo/Redo, `2.3` 재생.

## 2. 고정할 사용자 동작

1. 한 손가락 탭·드래그는 선택한 기존 도구가 허용하는 편집을 수행한다. 모든 도구에 새 드래그 기능을 추가하지 않는다.
2. 서로 다른 touch pointerId 두 개가 동시에 접촉하면 이동 모드로 전환한다. 정확히 같은 시각에 닿을 필요는 없다.
3. 두 번째 손가락이 닿으면 첫 손가락을 댄 이후 현재 제스처에서 발생한 편집 전체를 취소한다. 이미 반영한 셀도 복원한다. 이전에 손을 떼어 완료한 편집은 유지한다.
4. 편집 결과를 남긴 채 화면을 이동하려면 먼저 모든 손가락을 떼어 편집을 완료한 다음 두 손가락으로 다시 시작한다.
5. 두 손가락의 중심 이동량으로 가로·세로 스크롤한다. 손가락을 오른쪽으로 움직이면 악보 내용도 오른쪽으로 움직인다.
6. 이동 중 한 손가락이 떨어지면 이동을 멈춘다. 남은 손가락으로 편집하지 않으며 모두 뗄 때까지 대기한다. 대기 중 두 번째 손가락을 다시 대어도 제스처를 재개하지 않는다.
7. 세 번째 손가락이 닿으면 이동·편집을 중단하고 모두 뗄 때까지 대기한다. 이미 이동한 스크롤 위치는 유지한다.
8. 터치 취소·포커스 상실·문서 숨김 시 진행 중인 터치 편집은 취소하고 입력 예약·미리듣기를 정리한다. 완료된 편집과 이전 Undo/Redo는 유지한다.
9. 두 손가락 이동은 셀 입력·삭제·음 미리듣기·새 Undo 항목을 발생시키지 않는다.

## 3. 제스처 상태와 전이

포인터별 현재 좌표는 `Map<pointerId, { clientX, clientY }>`에 저장한다. touch만 등록하며 `pointerup`·`pointercancel` 때 해제한다. 브라우저가 보낼 수 있는 후속 click도 해당 제스처에서 중복 편집을 일으키지 않게 소비한다.

| 상태 | 입력 | 결과 |
| --- | --- | --- |
| idle | 첫 touch down | single: 첫 포인터와 편집 시작 기준 보관 |
| single | move | 기존 이동 임계값·도구 규칙에 따라 편집 |
| single | 정상 up | 탭 또는 드래그 완료, 유효한 순변경만 기존 이력 정책으로 확정 |
| single | 두 번째 touch down | 미반영 batch 폐기 → 현재 편집 복원 → 성공하면 pan 시작 |
| pan | 두 포인터의 move | 중심 이동량으로 scrollLeft/scrollTop 변경 |
| pan | 한 포인터 up | blocked: 모두 뗄 때까지 이동·편집 중단 |
| single/pan | 세 번째 접촉 또는 cancel | 현재 편집 취소, blocked에서 남은 접촉 종료 대기 |
| blocked | move 또는 추가 down | 편집·이동 금지. 접촉 수명만 추적 |
| blocked | 마지막 접촉 종료 | idle |
| 모든 상태 | blur/hidden | 미완료 편집 취소 및 입력 정리. 이전 포인터의 뒤늦은 move/up/click은 무시 |

한 번의 입력은 하나의 경로만 소유한다. 마우스·펜 제스처가 진행 중이면 터치가 이를 인수하지 않고, 터치 제스처 중 새 마우스·펜 입력도 병행 편집을 시작하지 않는다. 정상 단독 마우스·펜 입력은 기존 동작 그대로다.

추적되지 않은 포인터 이벤트는 편집을 시작하지 않는다. 포인터 캡처 해제·lostpointercapture를 처리할 때 정상 pointerup 뒤의 해제를 중복 취소로 해석하지 않는다. 순서가 바뀌어도 이미 끝난 제스처를 다시 완료·복원하지 않도록 식별자와 상태를 확인한다.

## 4. 현재 편집만 복원하는 경계

### 4.1. 현재 구현에서 재사용할 부분

- `edit_pointer_binding.ts`: 드래그 RAF batch, pointer capture, 도구별 편집과 미리듣기.
- `main.ts`: transaction 시작 시 `beforeLookup`, 실제 적용된 `edits`, 종료 시 순변경 patch 생성.
- `edit_history.ts`: 변경 좌표의 before/after patch 생성과 이전 값으로의 편집 목록 변환.
- 기존 편집 적용 경로: score/index·분석·렌더링·재생 산출물을 함께 갱신한다.

현재 `cancelScoreEditHistoryTransaction()`은 snapshot 참조만 버리고 악보를 복원하지 않는다. 이 함수의 의미를 마우스까지 일괄 변경하거나 일반 Undo를 자동 호출하지 않는다. 터치 제스처를 소유하는 transaction에 명시적인 rollback 경계를 추가한다.

### 4.2. 복원 계약

- 제스처 시작 기준을 첫 실제 셀 변경 전에 확보한다. 셀 변경 전 발생하는 단순 포커스·미리듣기와 악보 변경을 구분한다.
- 전체 AppState를 과거 값으로 대입하지 않는다. 해당 제스처가 변경한 좌표만 시작 값으로 복원하며, 원래 없었던 셀은 제거한다. 같은 셀을 여러 번 바꿔도 최초 값으로 돌아간다.
- 활성화된 여러 트랙과 note/global 편집 모두 실제 적용된 변경을 기준으로 포함한다.
- 복원 순서: RAF 취소 → pending edits 비우기 → 실제 반영된 변경의 역방향 patch 계산 → 이력 기록 없이 기존 편집 경로로 적용 → 결과 확인 → transaction 해제 → pan 또는 blocked로 전환.
- pending batch를 복원 직전에 flush하거나 복원 후 실행하지 않는다.
- 무변경 제스처의 취소는 기존 Undo를 소비하지 않는다. 복원은 새 Undo/Redo 항목을 만들지 않으며 시작 전의 undo/redo stack을 유지한다.
- 선택·범위·붙여넣기 preview 등 이 제스처가 바꾼 일시 UI 상태도 정리한다. 곡 정보·사용자 설정을 과거 snapshot으로 덮어쓰지 않는다.
- score 교체·도구/모드 전환·Undo/Redo·기타 구조 변경 전에 진행 중 제스처를 정리하는 경로를 마련한다. 같은 제스처 안에 다른 명령을 섞지 않는다.
- transaction에 문서 세대 또는 동등한 소유 확인을 둔다. 새 악보로 교체된 뒤 도착한 이전 pointer 이벤트나 rollback은 새 악보를 변경하지 않는다. 매 셀 편집에서 document 객체가 바뀔 수 있으므로 객체 동일성만으로 세대를 판별하지 않는다.
- 복원 실패를 성공으로 표시하지 않는다. 실패 시 pan 전환과 추가 편집을 막고 상태를 안내한다. score 변경 실패와 렌더링/재생 갱신 실패를 기존 edit effects 정책에 맞게 구분한다. 복원에 필요한 자료를 성공 전에 버리지 않는다.

## 5. 터치와 스크롤 연결

- 편집 모드의 악보 입력 영역에 `touch-action: none`을 사전 적용한다. 손가락 두 개가 닿은 뒤 CSS를 바꾸어 브라우저 스크롤에 넘기는 방식은 사용하지 않는다.
- 적용 범위는 악보 입력 영역이며 메뉴·편집 패널·팝업·페이지 전체 스크롤에는 전파하지 않는다. 보기 모드로 돌아가면 기본 터치 동작을 복구한다.
- `preventDefault()`와 pointer capture만으로 터치 스크롤을 차단했다고 판단하지 않는다.
- pan 시작 시 두 포인터의 현재 중심과 현재 스크롤을 기준으로 잡는다. 첫 손가락의 이전 이동량을 소급 적용해 화면이 튀지 않게 한다.
- 각 move에서 이전 중심과의 차이를 반대 부호로 현재 scrollLeft/scrollTop에 적용한다. 경계에서 clamp하며, 막힌 방향의 초과 이동량을 누적하지 않아 방향을 바꾸면 즉시 반응하게 한다.
- 기존 scoreArea scroll 경로를 통해 라벨 위치·viewport 렌더링을 동기화한다. 스크롤에 연동된 기존 seek 정책도 확인하여 중복 재생 제어를 추가하지 않는다.
- 핀치 거리는 확대에 사용하지 않는다. 편집 영역의 확대는 기존 앱 확대 컨트롤을 사용한다.
- 터치 편집 사용 시 “한 손가락 편집 · 두 손가락 이동”을 알 수 있는 간단한 안내를 제공한다. 기존 패널 배치를 크게 바꾸지 않는다.

- 기존 프로젝트의 `edit_pointer_binding.ts`, `main.ts`, `edit_history.ts`를 재사용 기준으로 검토했다. 범용 제스처 라이브러리 도입은 계획하지 않는다. 코드 차용이 필요한 새 판단이 생기면 출처·라이선스·범위를 별도로 기록한다.
