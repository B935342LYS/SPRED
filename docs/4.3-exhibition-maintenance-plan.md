# 졸업전시 준비 및 안정판 유지보수 계획

기준일: 2026-11-02
상태: 트랙 활성화 유지 완료·YouTube 허용치 250ms 복원 / Android 미설정 -220ms·iOS/iPadOS 0ms 제품 정책 확정

## 1. 작업 방향

- 학과의 주간보고서 제출 요구는 종료되었으며, 앞으로는 졸업전시 자료 제출과 전시 준비에 집중한다. 기존 보고서·보고서 초안은 이력으로 보존하되 정기 작성·동시 갱신을 자동 재개하지 않는다.
- 사용자 요청으로 MIDI import 등 3차 확장 기능 개발을 임시 중단한다. 기존 확정 정책과 실험 자료는 보존하며, 사용자가 재개를 요청하기 전에는 확장 설계·구현·의존성 설치를 자동 진행하지 않는다.
- 졸업전시 전까지 2차 구현 안정판의 유지보수를 우선한다. 확인된 결함과 필요한 좁은 범위의 구조 개선을 다루며, 전면 개편으로 확대하지 않는다.
- 전시 일정·제출 형식은 사용자에게 이미 정해져 있다. 사용자가 직접 진행하며 필요할 때 질의하므로 별도 확인을 선행 과제로 두지 않는다.
- 제품 경로는 `regression-code/`, 배포 사본은 `regression-code-test-publish/`다. 현재 기준은 원본 `09caa25`, 배포본 `dfa88cf`이며 트랙 유지·YouTube 100ms까지 배포했다.

## 3. 트랙 활성화 상태 유지

- 요구: 새 악보를 불러와도 사용자가 선택한 트랙 활성화 조합을 유지한다.
- 2.6 명세를 갱신했다. 최초 실행은 basic만 활성화하고, 악보 교체는 빈 배열을 포함해 기존 활성 목록을 유지한다. 초기 상태 생성에서 renderer에도 같은 목록을 전달한다.
- 진입점: `src/app/main.ts`의 `loadScoreJsonText`, `src/app/app_runtime.ts`의 초기 상태, `src/track/track_control.ts`, `docs/2.6-track-layer-ui-spec.md`.
- JSON 파일·Local Load·Examples의 공통 경로에서 확인한다. basic/optional/extra 조합 및 모두 비활성 상태, 활성 편집 트랙과의 관계, 재생 필터·표시 일치, 로드 실패 시 기존 상태 보존을 검증한다.
- 악보 교체 시 유지와 페이지 새로고침 후 영구 저장은 별개다. 이번 요구만으로 ScoreFile 저장 계약이나 localStorage 영구 설정을 추가하지 않는다. 애매한 선택 규칙은 구현 전 확인한다.
- 영향 경계: 앱 상태 및 트랙 제어. parser/analyzer 계약 변경을 전제하지 않는다.

## 4. YouTube 싱크 허용 오차 — 250ms 복원

- 2026-11-02 사용자 결정으로 100ms를 250ms로 복원했다. iPad 0~1초 반복은 재현 불가로 원인이 미확정이며, 안정성을 위해 의심 변경을 되돌리는 조치다. 원인 확정 또는 결함 해결 검증으로 간주하지 않는다.
- `youtube_sync.ts`의 `YOUTUBE_DRIFT_THRESHOLD_SECONDS = 0.25`를 적용한다. 검사 주기 1초·seek cooldown 500ms·재개 seek 생략 50ms는 유지한다.
- Local offset은 Android 미설정 -220ms, iOS/iPadOS·Windows 등 0ms, 기존 사용자 저장값 우선 정책을 유지한다.
- 원본·배포본 build(타입·라이선스 포함), test:youtube 통과. 양방향 249/250/251ms 경계, 200ms seek 생략 및 기존 binding/player 수명 검사를 확인했다.
- 실제 영상에서 반복 seek·영상/음성 끊김 재발 여부는 사용자 관찰 후 판단한다. 재발 시 악보 커서·YouTube 영상 위치·오디오 시계 진행을 구분하여 확인한다.
- 영향 경계: YouTube 재동기화 판단 상수. parser/analyzer·오디오 생성·저장 계약 변경 없음.

## 5. Local offset 초기값 정책 — 2026-11-02 iOS 관찰 반영

- 최신 배포: `cc84588`, Pages 실행 `41437124197` build/deploy success. 원본·배포본 build/test:youtube 및 로컬·공개 브라우저 환경 모사 검사 통과. iPad 0~1초 반복은 별도 원인 미확정 문제로 남기며 이번 보정값 변경으로 해결됐다고 간주하지 않는다.
- 사용자 본인에 이어 테스터 휴대폰에서도 -220ms일 때 싱크가 정상이라는 청취 관찰이 추가되었다. 사용자는 Windows 기본 0ms, 모바일 초기값 -220ms, 이후 사용자 변경값 보존을 정책으로 확정했다.
- 저장 키가 없을 때 Android로 식별되면 -220ms, iOS/iPadOS는 0ms를 사용한다. Windows는 터치 지원 여부와 관계없이 0ms이며 그 외·판별 불가 환경도 0ms다. 기존 저장값은 0을 포함해 우선한다.
- Windows UA를 우선 제외하고 Android UA만 확인한다. iPhone/iPad/iPod 및 Macintosh+멀티터치 판별은 제거했다. UA 위장·데스크톱 모드에서는 식별이 누락될 수 있다.
- 환경 기본값은 자동 저장하지 않는다. 키 부재는 실제 첫 방문과 동일하지 않으며, 저장소 삭제 시에도 환경 기본값을 다시 적용한다. 사용자가 change/Enter로 확정한 값만 기존 키에 저장한다. 저장값 오염·저장소 접근 실패 시 0ms, 페이지 내 사용자 조절값 보존은 기존 정책을 유지한다.
- 테스트 배포본 한정 예외를 종료하고 원본과 배포본에 같은 정책을 적용했다. 영향 경계는 브라우저 설정 읽기이며 ScoreFile·parser/analyzer·오디오 생성 계약은 바꾸지 않는다. 상세 기준은 3.7 최신 정책과 2.7을 따른다.
- 본 결정은 사용자 지정 기본값 정책이다. 모든 Android의 보편 지연이 측정된 것은 아니며 후속 사용자 보고에서 iOS는 0ms일 때 싱크가 맞는 것으로 관찰되어 기본값을 0ms로 수정했다. 테스터의 출력 경로·브라우저·기종별 후속 관찰에 따라 조정할 수 있다.
- 원본·배포본 build(타입·라이선스 포함), test:youtube 통과. Chrome 환경 모사에서 모바일 미설정값, 저장0/사용자값/오염, iPadOS 데스크톱 UA, Windows 터치·macOS 기본값, 재방문 및 수동0 저장을 확인했다. 실제 기기 지연 측정과는 구분한다.
- 배포 `58df8d9`, Pages 실행 `41435419998` build/deploy 성공. 공개 사이트 환경 모사 검사도 통과했다(pageerror 0).
