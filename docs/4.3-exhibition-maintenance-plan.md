# 졸업전시 준비 및 안정판 유지보수 계획

기준일: 2026-11-02
상태: 트랙 활성화 유지·YouTube 100ms 허용치 로컬 구현·자동 검증 완료(미배포) / 실제 영상 버벅임 관찰 대기 / 모바일 보정은 보류

## 1. 작업 방향

- 학과의 주간보고서 제출 요구는 종료되었으며, 앞으로는 졸업전시 자료 제출과 전시 준비에 집중한다. 기존 보고서·보고서 초안은 이력으로 보존하되 정기 작성·동시 갱신을 자동 재개하지 않는다.
- 사용자 요청으로 MIDI import 등 3차 확장 기능 개발을 임시 중단한다. 기존 확정 정책과 실험 자료는 보존하며, 사용자가 재개를 요청하기 전에는 확장 설계·구현·의존성 설치를 자동 진행하지 않는다.
- 졸업전시 전까지 2차 구현 안정판의 유지보수를 우선한다. 확인된 결함과 필요한 좁은 범위의 구조 개선을 다루며, 전면 개편으로 확대하지 않는다.
- 전시 일정·제출 형식은 사용자에게 이미 정해져 있다. 사용자가 직접 진행하며 필요할 때 질의하므로 별도 확인을 선행 과제로 두지 않는다.
- 제품 경로는 `regression-code/`, 배포 사본은 `regression-code-test-publish/`다. 현재 안정 기준은 원본 `88cb20a`, 배포본 `583a7a8`이며 악보 교체 시 테마 유지까지 배포했다.

## 3. 트랙 활성화 상태 유지

- 요구: 새 악보를 불러와도 사용자가 선택한 트랙 활성화 조합을 유지한다.
- 2.6 명세를 갱신했다. 최초 실행은 basic만 활성화하고, 악보 교체는 빈 배열을 포함해 기존 활성 목록을 유지한다. 초기 상태 생성에서 renderer에도 같은 목록을 전달한다.
- 진입점: `src/app/main.ts`의 `loadScoreJsonText`, `src/app/app_runtime.ts`의 초기 상태, `src/track/track_control.ts`, `docs/2.6-track-layer-ui-spec.md`.
- JSON 파일·Local Load·Examples의 공통 경로에서 확인한다. basic/optional/extra 조합 및 모두 비활성 상태, 활성 편집 트랙과의 관계, 재생 필터·표시 일치, 로드 실패 시 기존 상태 보존을 검증한다.
- 악보 교체 시 유지와 페이지 새로고침 후 영구 저장은 별개다. 이번 요구만으로 ScoreFile 저장 계약이나 localStorage 영구 설정을 추가하지 않는다. 애매한 선택 규칙은 구현 전 확인한다.
- 영향 경계: 앱 상태 및 트랙 제어. parser/analyzer 계약 변경을 전제하지 않는다.

## 4. YouTube 싱크 허용 오차 검토

- 사용자 결정(2026-11-02): 우선 250ms를 100ms로 줄이고, 버벅임이 있으면 다시 조정한다. 이번 작업은 2번까지만 진행한다.
- `youtube_sync.ts`의 `YOUTUBE_DRIFT_THRESHOLD_SECONDS = 0.1`(100ms)로 변경했다. `youtube_binding.ts`의 검사 주기 1초와 seek cooldown 500ms는 유지한다.
- 진입점: `docs/2.7-youtube-sync-ui-spec.md`, `src/app/youtube/youtube_sync.ts`, `src/app/youtube/youtube_binding.ts`와 player wrapper.
- 자동 검증: 양방향 99/100/101ms 경계와 기존 200ms 허용 구간의 보정 전환, YouTube binding/player 수명 검사 및 build(타입·라이선스 포함) 통과.
- 실제 영상에서 초기 재생/seek/일시정지·재개/loop 중 반복 seek·영상/음성 끊김 여부는 사용자 관찰 후 판단한다. 자동 검사 통과는 실제 청감 검증을 뜻하지 않는다.
- 5절의 고정 지연 보정과 시간에 따라 변하는 drift 보정은 구분한다. 같은 오차를 양쪽에서 중복 보정하지 않는지 확인한다.
- 영향 경계: 앱 YouTube 동기화·재생 제어. 오디오 생성 알고리즘의 전면 교체는 범위 밖이다.

## 5. Android -220ms 가설과 모바일 초기값

- 사용자 관찰: Android 기기에서 환경 구분 없이 약 -220ms가 일정하게 나타나는 것으로 보인다. 이것은 검증된 공통 특성이나 모든 모바일의 기본값 결정이 아니다.
- 조건부 방향: 해당 오차가 실제로 공통적으로 확인된다면, 지원 대상 모바일 환경의 최초 접속에서 YouTube Local offset 초기값을 -220ms로 자동 설정한다.
- 진입점: `docs/3.7-youtube-local-offset-spec.md`, `src/infra/youtube_preferences.ts`, `src/app/youtube/youtube_binding.ts`, 앱 초기 상태 및 기존 YouTube 테스트.
- 현재 Local offset은 `regression-code:youtube-local-offset-ms`에 저장되며 저장값 부재·오염·접근 실패 시 0ms다. 곡의 `musicData.youtube.offsetMs`와 사용자 환경용 Local offset을 구분한다.
- 검증 시 기기/OS/브라우저, 내장 스피커·유선·Bluetooth 등 출력 경로, 영상/악보, 네트워크·버퍼링 조건, 시작/재개/seek 및 반복 측정값을 기록한다. 측정 방법·기준 시점·부호 의미를 명시하여 -220ms 설정이 실제 오차를 줄이는지 확인한다.
- 동일 파일·영상으로 비교하고, 평균/분산과 예외 사례를 확인한다. 특정 기기나 출력 경로에서만 나타나면 전체 모바일 기본값으로 일반화하지 않는다. Android 관찰을 iOS 등으로 확대하는 것은 별도 근거와 범위 결정이 필요하다.
- 자동 초기값 적용을 검토할 때는 기존 저장값(사용자가 선택한 0 포함)을 덮어쓰지 않는 것을 기준으로 한다. 저장값 부재와 첫 방문, 저장소 삭제·차단/오염, 대상 환경 식별 방법을 구분하여 설계한다. 기기 식별 방식과 실패 시 동작은 아직 확정하지 않았다.
- 검증 전에는 현 기본값 0ms와 수동 조절을 유지한다. 검증 불충분 시 자동 -220ms 적용은 보류한다.

3. 3번 모바일 자동 보정은 보류한다. 별도 요청 없이 재개하지 않는다.
