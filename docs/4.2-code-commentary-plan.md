# 단계별 코드 주석 해설 계획

현재 상태: **2026-10-16 전체 108/108 파일 해설 및 종합 검증 완료.** 아래 작업 기록의 미완료/다음 위치는 당시 진행 상태다.

## 1. 목적과 적용 범위

2026-10-16 사용자 요청에 따라 모듈을 데이터 흐름 순서로 나누어 해설한다. 대상은 `regression-code-report-commentary-2026-10-15/`이다. 제품 코드와 CREPE 실험은 수정하지 않는다. [4.1 작성 가이드](4.1-code-commentary-guide.md)의 선언 JSDoc, 내부 처리·필드별 상세 `//` 기준을 따른다. 이 문서는 해설 계획이며 제품 명세를 대체하지 않는다.

각 단계도 작은 작업 단위로 나누어 읽기 → 주석 보강 → 검증 → 완료 기록 순으로 진행한다. 대형 파일은 함수군으로 나누고 일부만 다룬 파일을 전체 완료로 표시하지 않는다. 사용자가 변경하지 않는 한 아래 순서를 따른다.

## 3. 검증과 완료 기준

- 최초 작업 전 snapshot-manifest hash를 대조한다. 후속 작업은 직전 완료 상태를 함께 기준으로 삼는다.
- 동작·식별자·필드 순서·조건·반환값을 바꾸지 않는다. TypeScript 파서/프린터의 주석 제외 구문 비교로 확인한다. 타입 선언을 놓치지 않도록 JS 출력만으로 판정하지 않는다.
- 해설본의 정식 `npm run typecheck`, `npm run build`를 사용한다. 의존성 공유 방식과 미검증 사항은 기록한다. 기능 변경 없는 주석 작업에 전체 기능 테스트를 반복하지 않는다.
- 완료 파일·부분 범위·검증·다음 위치를 이 문서와 해설본 README에 남긴다. 발견한 결함은 별도 보고하고 주석 작업에서 수정하지 않는다.
- 이번 작업은 기존 코드 해설이며 신규 알고리즘·외부 코드 도입이 없어 별도 오픈소스 조사는 수행하지 않는다.
- 아래는 src의 TS 108개 파일 목록이다. JSON에는 주석을 넣지 않고 소비 코드에서 설명한다. dev 도구·테스트, HTML/CSS, 매뉴얼은 제품 TS 모듈 작업 후 별도 범위로 검토한다. 빈 파일은 종합 단계에서 용도와 상태를 확인하며 불필요한 구현을 추가하지 않는다.

## 5. 작업 기록

- 다음 단위: 1B 입력 크기·JSON 로드·구조 검증.

- 2026-10-16 원칙 보완: 의미가 명확한 단순 표현은 주석을 생략한다. 1A의 ok 판별값 및 주변 설명과 중복되는 score 필드 주석을 정리했다. 분기 계약과 참조 공유 설명은 유지한다.

- 2026-10-16 단순 표현 주석 정리 검증: create_runtime_document.ts의 주석 제외 TS 구문 동일성, typecheck, build 통과. 다음 작업 위치는 1B로 유지한다.

### 2026-10-16 1B-1 완료

- `score_limits.ts`: 모든 상수와 세 함수. UTF-16 length와 UTF-8 바이트, MiB/KiB 표시, offset 절삭·범위 제한과 import 거절의 차이를 설명했다.
- `json_load.ts`: 결과·오류 타입과 두 함수 전체. 용량 → JSON.parse → 루트 형태 → validator 위임, unknown과 예외 처리 범위를 설명했다.
- `score_validate.ts`: 모듈 설명, 오류/결과 타입, 상수 문맥, `validateScoreFile`, `validateRequiredTopLevelFields`까지 완료. 첫 오류 반환, Partial/as와 런타임 검사 차이, Map 재사용, 원본 참조 반환을 설명했다. 뒤의 세부 검사 함수는 읽어 호출 흐름을 확인했지만 주석 완료로 세지 않는다.
- 검증: 세 파일 원본의 manifest hash 일치, 주석 제외 TS 구문 동일성, 해설본 typecheck/build 통과. 제품 코드·검사 조건·오류 반환을 변경하지 않았다.
- 다음 위치: 1B-2 `validateYoutubeSyncShape`부터.

### 검토 중 확인한 명세·구현 차이

- 충돌 문서/소스: `docs/1.3-score-json-format.md` 2.10절과 `core/score/score_validate.ts`.
