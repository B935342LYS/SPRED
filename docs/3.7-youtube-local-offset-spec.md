작성일: 2026-09-19

최근 갱신: 2026-09-21 — 입력 확정·패널 접기·error:2 수정 Pages 배포 및 게시 사이트 실제 영상 확인.

- Video·곡 offset 즉시 적용: 구현·검증·Pages 배포 완료. 사용자 영상의 실제 API에서 확인한 error:2 수정도 포함한다. 배포 저장소 main `1a8884d`, Actions `35592417030` 성공. 13~19절의 기준과 17절의 최신 결정을 반영했다. 결과는 20~22절 참조. 원본 작업 저장소의 변경은 아직 커밋하지 않았다.

## 1. 목적과 결정 배경

악보와 YouTube 사이의 곡 고유 시간차와 사용자 환경에서 발생하는 재생 시간차를 분리한다. 사용자가 환경 보정값을 한 번 조절하면 같은 브라우저에서 재사용할 수 있게 한다.

사용자 실험에서 LAN 데스크톱과 Wi-Fi 노트북의 싱크는 일치했고, PC의 Chrome/Edge 및 핫스팟/Wi-Fi 비교에서도 차이가 없었다. Android 태블릿과 스마트폰에서는 오실레이터가 YouTube보다 약 200ms 빠르게 들렸다. 이는 사용자 청취 관찰이며 자동 계측 결과 또는 모든 Android 기기의 공통 특성으로 일반화하지 않는다.

이번에는 사용자 환경별 고정 보정을 도입한다. PLAYING 이벤트를 기다리는 새 시작 절차, 오실레이터 시작 시계 재정렬, Android 감지 후 일괄 -200ms 적용은 도입하지 않는다.

이 기능은 PC와 모바일 모두에서 사용할 수 있지만, 모바일 편집·Practice 지원 범위를 확대한다는 의미는 아니다.

## 2. 확정 요구와 세부 구현 기준

사용자 확정 요구:

1. 사용자 환경용 YouTube offset을 브라우저에 저장하고 재사용한다.
2. 기존 `Offset(ms)` 오른쪽에 `Local offset` 숫자 입력란을 둔다.
3. Video 입력란의 폭을 줄여 Video와 두 offset을 한 줄에 배치한다.
4. 기존 비동기 초기 동기화 명세를 이 방향으로 대체한다.

세부 구현 기준:

- 기본값 0ms, 허용 범위 -5000~+5000ms, 정수 1ms 단위.
- 유효한 값 확정 시 즉시 저장·적용한다. Reload는 기존 곡 설정 적용 용도로 유지한다.
- 0 입력으로 초기화한다. 추가 Reset 버튼은 배치하지 않는다.

사용자는 YL-1에서 범위 확대를 허용하고 YL-2·3의 권장안을 채택했다. 정확한 확대 수치는 구현 판단으로 ±5000ms를 선택한다. 결정 기록은 11절에 둔다.

## 3. 데이터와 저장 경계

| 값 | 의미 | 저장 위치 | 범위 |
| --- | --- | --- | --- |
| `musicData.youtube.offsetMs` | 곡의 악보와 영상 사이 시간 관계 | 기존 ScoreFile | 기존 ±60000ms 유지 |
| `youtubeLocalOffsetMs` | 이 브라우저·출력 환경에서 쓰는 YouTube 상대 보정 | 사용자 설정 및 localStorage | ±5000ms |
| Practice Input Sync | 마이크 입력 판정 시간 보정 | 기존 사용자 설정 | 변경 없음 |
| Practice Display offset | 노트 화면 표시 시간 보정 | 기존 사용자 설정 | 변경 없음 |

- localStorage 키 제안: `regression-code:youtube-local-offset-ms`.
- 같은 origin·브라우저 프로필 안에서 공통으로 사용한다. 악보·영상별 값이나 물리적 기기 ID별 값으로 분리하지 않는다.
- 다른 브라우저나 다른 사이트 주소에서는 별도 설정이다. 출력 장치가 바뀌면 재조절할 수 있다. UI에서 자동 기기 측정값인 것처럼 표현하지 않는다.
- 앱 초기화 시 한 번 읽는다. 키가 없거나 값이 유효하지 않으면 0ms를 사용한다.
- 유효한 수치는 정수 반올림·범위 제한한다. 저장값의 빈 문자열·NaN·Infinity·문자열 오염은 기본값으로 처리한다.
- 저장소 접근이 실패해도 페이지 메모리에서 값은 적용하며 앱이 중단되지 않게 한다.
- 새로고침·브라우저 재방문에는 복원한다. 악보 교체·YouTube off/on·Reload·track/layout 변경으로 초기화하지 않는다.
- ScoreFile 다운로드, 악보 local save, 예제 등록, undo/redo 및 문서 변경 표시에는 포함하지 않는다.
- 다른 탭의 변경을 실행 중 즉시 반영하는 동기화는 이번 범위에서 제외한다. 다음 초기화 시 저장값을 읽는다.

## 4. 시간 변환과 보정 방향

```text
effectiveOffsetMs = scoreOffsetMs + youtubeLocalOffsetMs
rawYoutubeSeconds = scoreSeconds - effectiveOffsetMs / 1000
youtubeSeconds = max(0, rawYoutubeSeconds)
```

- 음수 Local offset: 영상 목표 위치를 앞으로 이동한다. YouTube가 오실레이터보다 늦게 들릴 때 사용하는 방향이다.
- 양수 Local offset: 영상 목표 위치를 뒤로 이동한다.
- 예: scoreOffset=0, localOffset=-200, scoreSeconds=10이면 영상 목표는 10.2초다.
- 예: scoreOffset=+2000, localOffset=-200이면 유효 offset은 +1800ms이며 영상 시작 경계도 score 1.8초가 된다.
- 두 값을 각각 정규화한 뒤 합산한다. 합계는 ScoreFile의 ±60000ms 제한으로 다시 잘라내지 않는다. 합계는 계산용 값이며 파일에 저장하지 않는다.
- 합산은 공통 helper에서 한 번만 수행한다. 이미 합산한 값을 받는 하위 함수가 Local offset을 다시 더하지 않도록 계약을 명확히 한다.

Local offset은 오실레이터·score clock을 늦추는 값이 아니라 YouTube 목표 위치를 바꾸는 값이다. 0초보다 이전 위치는 표현할 수 없으며, 음수 보정 시 영상 앞부분 일부가 재생되지 않을 수 있다. 기존 YouTube offset과 동일한 시간 매핑의 성질이다.

±5000ms 확대는 숫자 연산·저장 형식에 문제를 추가하지 않는다. 다만 큰 음수는 영상 앞부분을 더 많이 건너뛰고, 큰 양수는 영상 시작 대기를 늘릴 수 있다. 짧은 영상에서는 목표 위치가 영상 끝을 넘을 수도 있다. 따라서 범위 확대를 재생 결과에 부작용이 전혀 없다는 뜻으로 보지 않으며, 이는 기존 offset과 동일한 의미의 사용자 조절이다. 기본값은 0으로 유지하고 ±5000ms·영상 시작 경계 사례를 검증한다.

## 5. 모든 YouTube 동기화 경로의 일관성

다음 경로는 동일한 유효 offset을 사용해야 한다.

1. mode on 또는 Reload의 최초 video load 위치.
2. stopped에서 Play, paused에서 resume.
3. 50ms 이내 재개 시 seek 생략 판단.
4. manual seek, loop wrap, Stop 후 0초 기준 정렬.
5. drift 검사와 재탐색 목표.
6. 영상 시작 전 구간 판단과 시작 경계까지 남은 시간.
7. 이미 재생 중인 상태에서 mode on 또는 Reload로 합류.

최초 seek에만 Local offset을 넣으면 기존 drift 보정이 나중에 이를 되돌리므로 일부 경로만 수정해서는 안 된다.

기존 1초 검사, 250ms drift threshold, 500ms seek cooldown 및 50ms 재개 위치 기준은 유지한다. score controller가 기준 시계이고 YouTube는 follower라는 역할도 유지한다.

## 6. UI 배치와 입력

기본 배치:

```text
Video [URL or ID]  Offset(ms) [곡 값]  Local offset(ms) [환경 값]
```

- 현재 YouTube 패널 안에서 Video·곡 offset·Local offset을 같은 행에 둔다. Reload·상태 표시의 기존 기능은 유지한다.
- 2026-09-20 UI 보완: 세 입력의 라벨을 입력창 아래로 옮기고 YouTube 버튼부터 Reload까지 위쪽 위치와 컨트롤 높이를 맞춘다. YouTube on/off 색상은 Edit Mode와 같은 기준을 사용한다(밝은·어두운 메뉴 테마 모두).
- Video 입력란의 과도한 가변 폭을 줄이되, 정규화된 11자 ID와 입력 여백을 표시할 수 있게 한다. 긴 URL 붙여넣기는 그대로 허용하며 입력 길이 제한을 UI 폭에 맞춰 줄이지 않는다.
- 문자열을 시각적으로 줄이는 것과 실제 값 변경을 구분한다. 기존 유효성 검사·ID 정규화 시점을 유지한다.
- 두 숫자 입력은 부호·최대 자릿수·스핀 버튼까지 들어가도록 최소 폭을 보장한다. `-60000`과 `-5000`이 잘리지 않아야 한다.
- 의도한 기본 패널 폭에서 한 줄을 검증한다. 화면 확대나 좁은 폭에서는 기존 상위 패널 배치와 함께 검토하며, 글자 축소·잘림을 강제하지 않는다. 공간이 부족한 극단적인 경우에는 줄바꿈을 허용한다.
- CSS는 `:first-child`에 따른 폭 배분 대신 Video/곡 offset/Local offset의 명시적인 class로 역할을 구분하는 방안을 우선한다.
- 각 label을 입력과 연결하고 키보드 포커스 순서를 Video → Offset → Local offset → Reload로 둔다.

설명 제안:

- 기존 `Offset(ms)`: 곡과 영상의 시작 위치 차이.
- `Local offset(ms)`: 이 브라우저의 재생 보정. YouTube가 늦으면 음수로 조절.

현재 숨김 도움말의 “이 기기에서 offset을 조절” 안내는 곡 offset과 환경 offset을 혼동하게 하므로 구분해서 갱신한다. 긴 저장 안내 문구를 패널 한 줄에 추가하지 않는다.

## 7. 적용 시점과 재생 상태

권장안은 **Local offset만 독립적으로 즉시 적용**하는 방식이다.

- 입력 중 매 글자마다 seek하지 않는다. 브라우저 change 이벤트 또는 Enter로 값을 확정한다. Enter가 중복 change와 겹쳐 동일 seek를 두 번 일으키지 않도록 값 변경 여부를 확인한다.
- 편집 중 `-` 또는 빈 칸은 중간 상태로 허용한다. 확정 시 유효하지 않으면 이전 적용값으로 복원한다. 0 입력이 명시적인 초기화다.
- 유효한 새 값은 정규화한 뒤 표시·런타임·localStorage에 반영한다.
- Local offset만 조절했을 때 아직 적용하지 않은 Video/곡 offset 입력을 저장하거나 Reload하지 않는다. 현재 적용된 ScoreFile 값과 결합한다.
- YouTube off이면 설정만 저장하고 영상을 켜지 않는다. 다음 mode on에 반영한다.
- player가 준비되지 않았으면 저장하고, 준비 완료 시 과거에 캡처한 local 값이 아닌 최신 값을 사용한다.
- 재생 중이면 score time을 유지한 채 YouTube만 새 위치로 한 번 정렬한다. 250ms보다 작은 변경도 명시적 사용자 조절이므로 적용한다.
- paused/stopped이면 영상 위치만 정렬하고 일시정지를 유지한다. 새로 play하지 않는다.
- 기존 영상 시작 timer는 취소하고 새 경계로 재계산한다. 재생 중 새 목표가 음수면 영상을 0초에 멈추고, 이후 기존 경계 예약 정책을 따른다.
- 명시적 재정렬 후 기존 seek cooldown 상태도 갱신한다. 오래된 timer가 나중에 잘못 재생하지 않도록 한다.
- 저장값이 적용돼도 기기/네트워크 지연이 매번 달라지면 완전히 맞지 않을 수 있다. 고정 보정과 가변 준비 지연을 혼동하지 않는다.

## 8. 모듈 경계와 구현 순서

영향 경계는 YouTube UI/binding, 사용자 설정 저장, 순수 시간 계산이다. parser/analyzer, ScoreFile 형식, 오실레이터 backend, Practice 점수 공식과 입력/화면 보정은 변경하지 않는다.

1. 사용자 설정 모듈에 Local offset 정규화·load/save를 추가한다. 파일명 후보는 `infra/youtube_preferences.ts`이며 game 설정과 개념을 섞지 않는다.
2. AppState/초기화 경로에 사용자 설정값을 연결한다. 악보 교체·runtime 재구성이 값을 보존하는지 확인한다.
3. `youtube_sync.ts`에 합산 helper를 두고 binding의 모든 계산 경로에서 사용한다. 기존 순수 함수에는 합산 완료 값을 전달하는 방식을 우선한다.
4. DOM/type/HTML/CSS에 입력란과 배치를 추가한다.
5. Local 입력의 독립 저장·재정렬 경로를 연결한다. 기존 Reload는 곡 메타데이터 저장 역할을 유지한다.
6. 한글·영어 매뉴얼의 YouTube 설명에 곡 offset과 Local offset, 부호 방향, 저장 범위를 반영한다.
7. 테스트·실제 브라우저 확인 후 배포 여부를 결정한다.

새 함수·타입은 기존 JSDoc 및 핵심 처리 블록 주석 규칙을 따른다. 준비 Promise나 재생 상태기계의 광범위한 재설계는 수행하지 않는다.

## 9. 검증과 완료 기준

### 자동 검증

- 합산: 양/음/0, 두 값의 상쇄, 최대 곡 값과 Local 값 합산, 중복 적용 없음.
- 저장: 기본값, 1ms 값 보존, 범위 제한, 오염값, 접근 실패, 새 초기화의 복원.
- 독립성: ScoreFile JSON·문서 수정 상태·undo 이력·Practice 두 보정값이 변하지 않음.
- 같은 유효 offset으로 load/play/resume/seek/stop/loop/drift/영상 시작 경계를 계산함.
- Local 조절 뒤 drift가 곡 offset 기준으로 되돌리지 않음.
- 입력 중간 상태, Enter/change 중복, YouTube off, loading 중 값 변경, paused 적용.
- 대기 timer가 새 보정에 맞춰 취소·재예약되고 늦은 이전 작업이 새 값을 덮어쓰지 않음.
- `test:youtube`, `build` 및 저장/상태 경계에 필요한 회귀 검증. 새 테스트는 프로젝트의 정의된 실행 경로에 연결한다.

### 브라우저·사용자 확인

- 기본 화면에서 세 입력을 한 줄로 표시하고 ID·음수 숫자·스핀 버튼이 겹치거나 잘리지 않음. 확대/좁은 폭에서 사용할 수 있음.
- ±1ms 직접 조절과 새로고침 복원, 악보 교체 후 유지, 곡 다운로드의 원래 offset 보존.
- 미리 적용하지 않은 곡 입력과 Local 변경이 서로 섞이지 않음.
- 영상이 늦는 환경에서 Local -200ms를 기준으로 조절해 같은 악보의 첫 재생·재개·탐색 후 재생을 반복 비교한다.
- Local 0ms의 PC 동작은 기존과 동일하다. 모바일 비교는 이 기능의 효과 확인이며 모바일 전체 기능 지원 검증은 아니다.
- 미디어 시각 차이와 실제 청감 차이를 구분하고, 관측하지 않은 환경까지 개선됐다고 일반화하지 않는다.

## 13. 확장 목적과 작업 범위

Video·곡 offset도 Local offset처럼 입력을 확정하면 반영하도록 통일한다. Reload는 설정 적용 버튼에서 확정된 설정으로 영상을 다시 읽는 버튼으로 역할을 분리한다. 이 문서는 사용자의 명세 작성 요청에 따라 작성했으며 구현 완료를 뜻하지 않는다.

대상은 `regression-code/`의 YouTube 입력/binding·player wrapper·상태 타입, 패널 표시용 HTML/CSS·DOM 연결, 곡 메타데이터 갱신, 관련 테스트와 한글·영어 매뉴얼이다. player wrapper 변경은 오류 전달·요청 수명·재시도에 필요한 범위로 제한한다. ScoreFile 형식, parser/analyzer 계약, 오실레이터 스케줄, Practice 판정·두 Sync 값, 기존 drift 정책은 변경하지 않는다. 배포 사본 동기화와 원격 게시 여부는 구현·검증 후 별도로 기록한다.

## 14. 입력 확정과 데이터 계약

### 14.1. 공통 확정 규칙

- 매 글자 `input` 이벤트에서 저장·seek·로드하지 않는다. Local과 같은 `change` 또는 Enter를 확정 경계로 사용한다.
- Enter와 뒤따르는 change가 중복돼도 정규화된 적용값이 같으면 문서 갱신·seek·로드를 반복하지 않는다. IME 조합 중 Enter는 확정 처리에서 제외한다.
- 각 입력은 독립적으로 확정한다. 곡 offset 확정은 적용된 videoId와 결합하며 다른 입력의 미확정 DOM 값을 읽지 않는다. Local도 적용된 곡 offset만 사용한다.
- 정상 확정한 Video는 정규화한 ID를 표시한다. 같은 영상을 가리키는 URL로 바꿔도 ID가 같으면 재로딩하지 않는다.
- 숫자는 기존 범위·정수 정규화 정책을 유지한다. 곡 offset ±60000ms, Local ±5000ms이며 빈 숫자·비유한 값은 이전 적용값으로 복원한다. 0은 유효한 명시적 값이다.
- 잘못된 비어 있지 않은 URL/ID는 저장하지 않고 기존 영상·문서·재생을 유지하며 오류를 알린다. 잘못된 입력은 입력창에 남겨 수정할 수 있게 한다(YI-3). 입력 오류를 player 오류로 취급하여 동작 중인 영상을 끄지 않는다.
- 빈 Video 확정은 `videoId: ""`를 저장하고 영상 재생·요청·예약을 해제한다. 토글은 켠 채 영상 없는 대기 상태로 남겨 다음 링크를 입력할 수 있게 한다. 곡 offset과 Local은 유지하며 악보 재생 자체를 멈추지 않는다.
- 값 변경으로 발생한 UI 갱신이 다른 입력의 미확정 편집 내용을 덮어쓰지 않아야 한다.

### 14.2. 문서 변경과 연산 경계

| 조작 | ScoreFile | 사용자 설정 | 영상 동작 |
| --- | --- | --- | --- |
| 새 Video 확정 | videoId 및 updatedAt 갱신 | 유지 | on이면 대기/error에서도 새 영상 로드; off에서는 UI 입력 불가 |
| 곡 offset 확정 | offsetMs 및 updatedAt 갱신 | 유지 | ready/on이면 위치 재정렬 |

- `musicData.youtube` 이외의 음악 메타데이터·악보 셀·레이아웃은 유지한다. 변경된 곡 설정은 이후 JSON 다운로드·악보 Local Save에 포함하지만 확정 자체가 악보 자동 저장을 뜻하지 않는다.

- 같은 값 확정과 Reload는 `updatedAt`을 갱신하지 않는다.

## 15. 영상 적용·재생 상태·비동기 경합

### 15.1. 상태별 처리

| 상황 | 동작 |
| --- | --- |
| ready/on에서 곡 또는 Local offset 변경 | 현재 score time 기준으로 강제 재정렬; 영상 load 없이 seek |
| playing에서 on 상태의 Video 변경 또는 Reload | 악보 시계는 계속 진행; 새 영상 준비 시점의 현재 score time에 합류 |
| paused/stopped에서 on 상태의 Video 변경 또는 Reload | 준비 후 현재 악보 위치로 정렬하고 영상 일시정지 유지 |
| loading 중 offset 변경 | 최신 값을 저장; 준비 완료 시 최신 합산 offset으로 정렬 |
| loading 중 다른 Video 확정 또는 Reload | 가장 최근 요청만 상태·영상·재생을 확정할 수 있음 |
| YouTube off | 버튼만 표시. 영상 재생·drift·시작 예약 중지; 입력·Reload 접근 불가 |
| off에서 토글 on, 저장 ID 있음 | 패널을 열고 저장된 영상 로드; 현재 악보 위치·재생 상태에 맞춤 |
| off에서 토글 on, 저장 ID 없음 | 패널을 열고 영상 없는 대기 상태 유지; 링크 입력 허용 |
| 패널이 열린 대기/error 상태에서 offset 변경 | 저장만 수행; 영상 로드·자동 재시도하지 않음 |
| 패널이 열린 대기/error 상태에서 유효한 새 Video 확정 | 새 설정 저장 후 로드·복구 시도 |
| 패널이 열린 error 상태에서 Reload | 유효한 저장 ID로 재시도; 준비 후 현재 controller 위치·재생 상태에 맞춤 |
| 유효한 저장 ID가 없는 상태에서 Reload | 로드하지 않고 영상 설정이 없음을 알림; 패널과 토글은 열린 상태 유지 |

Reload는 입력창의 잘못된 URL을 저장하거나 로드하지 않고 마지막으로 확정된 ID를 사용한다. 잘못된 입력은 수정할 수 있도록 남기며 입력 오류와 영상 로딩 상태를 구분해 표시한다.

영상 목표·시작 경계·drift는 항상 최신 곡 offset + Local offset을 사용한다. 명시적 offset 변경은 기존 seek cooldown과 drift threshold로 생략하지 않는다. paused/stopped 상태에서는 자동 재생하지 않는다. error에서 동일 ID를 다시 확정하는 것은 동일 값 무동작 규칙을 따르며, 재시도는 Reload를 사용한다.

offset 변경·영상 교체·Reload·off 전환 시 이전 영상 시작 timer를 취소한다. ready/on/playing일 때만 새 경계를 예약하며, 음수 목표 위치는 기존 0초 대기 정책을 따른다.

### 15.2. 늦은 요청과 실패 처리

- 요청 세대 번호 또는 동등한 방식으로 이전 로드 완료·실패·player callback을 무효화한다. 예: A 로딩 중 B 확정 후 A 완료가 B를 덮어쓰면 안 된다.
- off 전환, 빈 Video 확정, 악보 교체, dispose 이후 이전 비동기 작업이 영상을 켜거나 상태를 ready/error로 바꾸지 못하게 한다.
- player 생성 중 연속 요청으로 iframe/player가 중복 생성되거나, 같은 player의 겹친 load가 뒤늦게 이전 영상을 선택하지 않도록 생성·로드 수명을 제어한다. Promise 반환 후 상태 확인만으로 해결됐다고 간주하지 않는다.
- 새 영상 요청 전에 이전 영상의 재생·drift·시작 예약을 중지한다. 최신 영상 준비 후 controller의 최신 재생 상태를 조회한다.
- 유효한 ID 저장과 외부 영상 로딩 성공을 구분한다. 네트워크·임베드 제한으로 로딩이 실패해도 저장된 ID를 자동으로 이전 값으로 되돌리지 않는다. 악보 재생을 유지하고 오류를 표시하며 Reload로 재시도할 수 있게 한다.
- 영상 오류는 토글을 끄지 않고 열린 패널에서 표시한다. Reload는 유효한 저장 ID로 다시 시도한다(YI-2 최신 결정). 기존 비동기 초기 PLAYING 대기나 오실레이터 시계 재설계는 도입하지 않는다.

### 15.3. YouTube 버튼과 패널 표시

- 버튼은 사용자가 YouTube 기능을 사용하려는지 나타낸다. 체크 여부를 영상 로딩 성공/실패 표시로 겸용하지 않는다.
- 개념상 활성 의도 `enabled`와 영상 상태 `idle/loading/ready/error`를 분리한다. 실제 타입은 동등한 상태 조합으로 구현할 수 있으며, on이면서 영상이 없는 상태를 반드시 표현한다.
- off이면 YouTube 버튼만 남긴다. Video·곡 offset·Local offset·Reload·상태 표시·영상 영역과 이 영역용 여백을 숨긴다. 숨겨진 입력은 Tab 탐색·접근성 트리에 노출하지 않는다.
- on이면 입력·Reload·상태를 표시한다. 영상 영역은 loading/ready일 때 표시하고 대기/error에서는 입력과 오류 복구 UI를 유지한다.
- 사용자 off는 YouTube 재생과 예약만 중지한다. 악보 controller·오실레이터·Practice 세션을 중지하거나 초기화하지 않는다. 설정값과 updatedAt도 바꾸지 않는다.
- 토글 off/on만으로 입력 중이던 잘못된 URL을 지우거나 저장값으로 덮어쓰지 않는다. 다시 켤 때 로드는 확정된 ID를 사용하고 잘못된 입력의 오류 표시는 별도로 유지한다. 초기화·악보 교체는 새 악보 값으로 입력을 채우고 패널을 닫는다.
- 토글 클릭 전 blur/change가 발생하면 기존 확정 규칙으로 처리하되, 뒤따르는 off가 모든 영상 요청보다 우선한다. 닫기 자체로 다른 입력을 강제 일괄 저장하지 않는다.
- 접을 때 내부에 포커스가 남지 않도록 버튼으로 돌린다. 버튼의 키보드 조작과 펼침 상태 접근성 정보를 함께 갱신한다.
- 패널 개폐로 실제 악보 viewport 크기가 변하면 기존 크기 변경 대응을 사용한다. 메타데이터만 바꿀 때의 전체 Canvas 재그리기 금지와 실제 viewport 크기 변경에 필요한 재배치는 구분한다.

## 20. 로컬 구현과 검증 결과 — 2026-09-21

- `youtube_binding.ts`: `enabled`와 `idle/loading/ready/error`, 입력 오류를 분리했다. Video·곡 offset·Local의 change/Enter 개별 확정, 동일 값 무동작, 빈 링크의 열린 idle 상태, 저장 ID 기반 Reload를 연결했다.
- 패널 off는 입력·Reload·상태·영상·여백을 숨기고 player와 예약을 정리한다. 오류에서도 패널을 유지한다. 초기화·악보 교체만 입력 전체를 채우며 토글 왕복은 잘못된 입력과 확정 설정을 보존한다.
- metadata 적용은 score만 교체하고 indexes·분석·렌더·편집 이력·audio runtime을 유지한다. 변경 후 전체 `session.render()` 호출을 제거했다.
- 영상 변경·Reload·off에서 세대 번호와 AbortController로 이전 요청을 무효화한다. 영상마다 player와 소유 mount를 분리하여 이전 dispose/error가 새 iframe을 훼손하지 않도록 했다. offset 변경은 재생성하지 않는다.
- API script 준비는 공유하되 개별 호출 대기는 취소 가능하다. API/플레이어 준비에 10초 제한을 두고 실패 캐시·timeout·callback·소유 mount를 정리한다. 일반 영상 오류도 전달한다. `loadVideo()` 완료는 cue 명령 전달이며 실제 CUED/PLAYING 확인을 뜻하지 않는다.

## 21. 실제 영상 error:2 수정 — 2026-09-21

- 사용자 보고: 악보 영상 `gpcRRvCuXfs`와 다른 악보들에서 `YouTube player error: 2`가 발생했다.
- 재현: 실제 API에 영상 ID 없이 player를 생성하면 `/embed/`가 열리고 `ready → error:2`가 도착했다. 같은 ID를 생성 옵션에 지정하면 `/embed/gpcRRvCuXfs`가 열리며 오류 없이 준비됐다. 새 일반 오류 처리 경로가 빈 초기 영상의 오류까지 실패로 처리한 회귀다.
- 수정: `createYoutubePlayer()`에 확정 videoId를 필수 인수로 전달하고 `YT.Player` 생성 옵션에 즉시 지정한다. 이후 최신 악보 위치로 cue/seek하는 절차는 유지한다. 오류 2를 무조건 무시하거나 정상 오류 검사를 약화하지 않는다.
- 회귀 테스트: binding이 확정 ID를 생성기에 전달하는지, 실제 wrapper가 생성 옵션에 ID를 넣는지 검사 추가. `test:youtube`, `build`, 기존 Chrome 모의 회귀 스크립트 통과.
- 실제 Chrome에서 사용자 ID를 넣은 ScoreFile 로드 → on → Reload → Play/Pause → off/on을 확인했다. error:2 및 페이지 오류 없이 동작했고, 영상 요소에서 약 2.93초·paused=false·readyState=4를 관측했다. 공식 예제 ID `M7lc1UVf-VE`도 Ready를 확인했다.
- 검사 과정에서 소스 요청을 가로채는 계측 실행은 API ready timeout으로 실패했다. 가로채기 없이 실제 앱을 실행하고 iframe 메시지·영상 요소를 관측한 최종 검증이 통과했다. 모든 네트워크·기기에서 timeout이나 청감 오차가 없다는 의미는 아니다.
- 로컬 증거: `.agents/tmp/compare-youtube-init.cjs`, `test-youtube-error2-fixed.cjs`, `youtube-error2-fixed.png`. 실제 사용자 환경의 음향 싱크 확인과 배포는 별도이며 커밋·푸시는 수행하지 않았다.
